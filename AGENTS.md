# Работа с COMPLAN

## Проект

COMPLAN — браузерный 3D-планировщик коммуникаций. Стек: React, TypeScript, MobX, Three.js и Vite. Интерфейс и документация — на русском языке. Подробности пользовательских сценариев и ограничения моделей описаны в `README.md`.

## Окружение и команды

- Node.js: 20.19+ или 22.12+.
- Используйте pnpm; версия закреплена в `packageManager` файла `package.json` (сейчас 9.15.0).
- Единственный lock-файл — `pnpm-lock.yaml`. Обновляйте его вместе с зависимостями через pnpm; не создавайте `package-lock.json` или `yarn.lock`.

```sh
pnpm install --frozen-lockfile
pnpm run dev
pnpm run typecheck
pnpm test
pnpm run build
pnpm run preview
```

Для изменения зависимостей используйте `pnpm add`, `pnpm add -D` и `pnpm remove`.

Браузерные проверки:

```sh
pnpm exec playwright install chromium
pnpm run test:browser
```

Playwright сам запускает Vite на `127.0.0.1:4174`; порт должен быть свободен. Сборка включает проверку типов. Публикация на GitHub Pages настроена в `.github/workflows/pages.yml`; сохраняйте относительный `base: './'` в конфигурации Vite.

## Карта исходного кода

- `src/main.tsx` — запуск React, StrictMode и подключение стилей.
- `src/App.tsx` — компоненты интерфейса, каталог, инспектор и спецификация.
- `src/store.ts` — MobX-хранилище фильтров, длин, цветов, спецификации и команд интерфейса.
- `src/interface.ts` — адаптер между контроллером редактора и хранилищем.
- `src/editor.ts` — сцена Three.js, манипулятор, выделение, обработчики ввода, рисование трассы и применение команд истории.
- `src/catalog.ts` — каталог и параметры компонентов.
- `src/elements.ts` — геометрия, порты, совместимость и цвета деталей.
- `src/connections.ts` — граф соединений и преобразования связанных сборок.
- `src/route.ts` — подбор деталей и сборка трассы по точкам.
- `src/project.ts` — сериализация, проверка загружаемых проектов и спецификация.
- `src/history.ts` — история команд со снимками состояния.
- `src/*.css` — стили интерфейса.
- `tests/*.test.js`, `tests/*.test.ts` — модульные тесты на `node:test`, запускаемые через `tsx`.
- `tests/browser/` — сценарии Playwright.

## Правила изменений

- Новый код приложения пишите на TypeScript/TSX. Сохраняйте стиль соседнего кода: ESM, одинарные кавычки, точки с запятой, отступ в два пробела. В локальных импортах используется расширение `.js`, разрешаемое в TypeScript-модули.
- Не ослабляйте проверку типов ради прохождения сборки. В проекте включён `noImplicitAny`; полный режим `strict` пока не включён.
- Состояние интерфейса изменяйте методами MobX-хранилища; компоненты, читающие наблюдаемые данные, оборачивайте в `observer`. Вычисляемые списки и итоги получайте из состояния, а не храните вторую копию.
- Не помещайте объекты Three.js в глубокое наблюдение MobX. Передавайте в интерфейс снимки данных; ссылки на команды и строки спецификации сейчас используют `observable.ref`.
- Учитывайте переходную архитектуру: React создаёт разметку, но контроллер обновляет часть полей инспектора и элементов управления через DOM. При изменении `id`, `data-*` или структуры разметки проверяйте обращения в `src/editor.ts` и браузерных тестах. При переносе участка на React убирайте прежние DOM-обновления этого же участка.
- Инициализация редактора должна корректно переносить повторный запуск эффекта в StrictMode. Освобождайте обработчики, таймеры, наблюдатели, цикл отрисовки и ресурсы Three.js при размонтировании. Учитывайте совместное использование материалов при освобождении ресурсов.
- Документацию, комментарии и пользовательские сообщения пишите по-русски; идентификаторы и API оставляйте на английском.
- Перед изменениями проверяйте рабочее дерево. Сохраняйте существующие пользовательские изменения; не редактируйте сгенерированные `dist/`, `node_modules/`, `test-results/` и `playwright-report/` вручную.

## Инварианты редактора

- Единицы проекта — миллиметры. Мировая ось Y направлена вверх; локальная ось X трубы идёт от гладкого конца к раструбу.
- Соединяйте только свободные совместимые порты. Один порт участвует максимум в одном соединении; циклы внутри сборки запрещены.
- Перемещение сборки, изменение длины и поворот ветки должны сохранять геометрию стыков.
- Изменения проекта должны поддерживать undo/redo. Одно перетаскивание с магнитной стыковкой — одна команда; движения камеры не входят в историю. Текущий лимит — 10 команд.
- При изменении формата сохранения сохраняйте чтение проектов версий 1, 2 и 3. Проверяйте входной JSON до замены сцены.
- Обновляйте спецификацию после добавления, удаления, перекраски, изменения длины, открытия проекта и восстановления истории. Цвет и длина влияют на группировку строк.

## Проверка результата

- После изменения кода запускайте `pnpm test` и `pnpm run build`.
- После изменения интерфейса, DOM-адаптера, событий, жизненного цикла Three.js или взаимодействий редактора запускайте также `pnpm run test:browser`.
- Для исправлений поведения добавляйте тест на соответствующий сценарий: геометрия и формат проекта — модульные тесты; взаимодействия пользователя — браузерные.
- Для правок только документации достаточно проверить актуальность путей и команд и выполнить `git diff --check`.
- В итоговом сообщении указывайте выполненные проверки и обнаруженные ограничения. Не утверждайте, что проверки прошли, если они не запускались или завершились ошибкой.
